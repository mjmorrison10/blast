# BLAST: AI ops UX — timers, thinking toggle, timeouts, persistent errors

## Goal
Owner: BLAST sometimes "runs forever and just… nothing," sometimes fast,
sometimes slow — no visibility, no error. Stack-wide asks: elapsed timer +
learned "typically ~Ns" on every AI op, a thinking toggle (default ON, "Fastest"
turns it off), and errors that stay visible.

## Root causes (confirmed)
- NO fetch timeout anywhere in llm.js — a hung request freezes the button
  forever (catch/finally never run). That is the "forever and nothing".
- thinkingConfig:{thinkingBudget:0} hardcoded since the 7/22 speed-up — no
  quality option.
- Errors are a single 6s toast; nothing persists.
- Bonus bug: the >14MB Files-API poll URL uses encodeURIComponent on
  "files/abc" → 400 on every poll (recall fixed this with geminiFileResourceUrl).

## Changes
- **llm.js**: `fetchWithTimeout` helper (per-attempt AbortController; abort →
  catchable "… timed out — check your connection and try again"). Deadlines:
  GEN 180s, UPLOAD_START 30s, UPLOAD 900s (2GB is legitimately slow), POLL 15s.
  Wrap fetches at :102/:122/:140/:185/:228/:278/:313 (delete stays best-effort).
  Port recall's thinking opts (opts.thinking / opts.thinkingBudget; default
  thinkingBudget:0) into both generationConfig builders. RIDER: port
  geminiFileResourceUrl into waitForGeminiFileActive + deleteGeminiFile.
- **app.js**: `blast_ai_ms_v1` (op-keyed last-5 durations: adapt /
  suggest-text / suggest-vision / suggest-transcribe) + recordAiMs/typicalAiMs;
  `blast_thinking_v1` + StackData shared `aiThinking` ("on"/"off", shared wins,
  default on, persisted on radio change — NOT via #keysave which rewrites
  settings wholesale); `aiRun(op, labelEl, errEl, baseText, fn)` helper (ticker
  into the existing label, onPhase threading, duration record, persistent error
  write, rethrows). Adapt + suggest handlers wrap via aiRun; text/vision calls
  get `thinking: pref==="on"`, the transcription step is always thinking-off.
- **index.html**: `#adaptError` + `#suggestError` aria-live divs; thinking
  radio row in the settings modal under the provider block.
- **style.css**: `.ai-error` (hidden until `.on`, danger color, persists until
  the next run).
